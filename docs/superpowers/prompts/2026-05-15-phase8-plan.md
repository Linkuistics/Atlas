### Plan author's job

Take the brainstorm's four-work-item shape and turn each into a plan section with:

- **File-by-file deliverables.** Every file the work item touches: created, modified, deleted. Where the brainstorm names a specific line (e.g., `mod.rs:1167` for the auditor HardFail emit site), the plan section confirms or refines it after re-reading the worktree.
- **Exact diffs where tractable.** For schema changes (WI-1's `LlmRequest`), prompt-text changes (WI-3's rubric rewrite), and code-deletion targets (WI-3's file removals), show the diff or the replaced text. For larger structural changes, code-sketch the new module shape.
- **Per-work-item acceptance criteria.** Cargo gates, polyglot smoke regression-guard expectations, test files added, env-var preconditions.
- **Test coverage table.** New test files per work item, what each asserts, whether they're `#[ignore]`-gated or CI-active. The brainstorm names specific test paths (`llm_request_rendered_prompt_smoke.rs`, `agent_runtime_hardfail_emission.rs`, `cargo_retirement_smoke.rs`); the plan locks these.
- **Risk register.** Reproduce brainstorm §9's R1–R12 as plan §12 with the same numbering. Add any new risks that surface during plan-time worktree re-reading. Each risk needs a concrete mitigation owner (which work item handles it).
- **Memory updates.** Specify exactly which memory files WI-4 touches: at minimum `project_phase4_plus_roadmap.md` (Phase 8 SHIPPED entry + Phase 9 unblocked flag) and `MEMORY.md` (index-line description refresh). If the open framing question above resolves toward globalised "work item" terminology, add the text-refresh memory edits to WI-4's checklist too.
- **Cumulative regression-guard expectation per work item.** WI-1 and WI-2 hold the existing polyglot release smoke baseline (~40 cold calls). WI-3 may require recalibration if the polyglot fixture has Cargo content (brainstorm §6.5 names the contingency). The plan locks the empirical pre-flight: grep `crates/atlas-cli/tests/fixtures/` for `Cargo.toml` at plan-time so WI-3 doesn't discover it mid-flight.
- **LOC envelope per work item.** Brainstorm §3's table is rough. Plan tightens to ranges where possible — e.g., WI-1 atlas-llm Δ is +120 ± 20 LOC across four backends + router + schema.
- **Commit decomposition guidance per work item.** Two-commit shape (code commit + status flip) vs. one-commit shape vs. multi-code-commit, mirroring the prior sprint's per-PR decomposition decisions.

They are dropped (per precedent `7d6f6f3` / `f9315f6` / `ca93814`) in the status-flip commit of the work they kick off. This prompt has no work-item number — it's a session-kickoff prompt for the plan-authoring session — but the same drop-on-completion convention applies: when the Phase 8 plan ships its status-flip commit, this prompt gets dropped in that same commit.
